# 게시용 블로그 원고 완성

## 작업 내용

- 기존 실험 요약 초안을 문제 제기부터 재현까지 이어지는 게시용 글로 확장했습니다.
- 카테고리는 `개인 프로젝트` 하나로 두고 기술 키워드는 태그로 분리했습니다.
- 공개 저장소와 고정 merge commit의 원본 결과 링크를 추가했습니다.
- 합성 실험, 3회 표본, 관측 정밀도와 운영 기능 미구현 범위를 명시했습니다.

## 변경 전후

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 형식 | 짧은 실험 요약 | 제목·설명·카테고리·태그가 있는 게시용 Markdown |
| 구현 설명 | 결과 중심 | 재시도 예산, Jitter 계산, DLQ와 낙관적 락 흐름 포함 |
| 측정 설명 | 핵심 지표 요약 | 원시 시각 bucket, 대조군, 입력 통제와 해석 주의점 포함 |
| 재현성 | 저장소 내부 상대 링크 | 공개 GitHub 원본 링크와 전체 실행 명령 포함 |
| 결론 | 간단한 한계 | 빠른 완료·부하 분산·실패 보존을 분리해 해석 |

## 실제 검증 결과

- `python scripts/verify-report.py results/stage6-20260904T150000Z` 성공
- 원본 JSON, summary, retry bucket, CSV, 실험 보고서와 블로그 표 일치
- 고정 커밋 `e2527c5`의 공개 링크 대상 4개가 Git에 존재함을 확인
- 비밀번호·토큰·payload를 원고에 추가하지 않음

## 다음 단계

사용자가 원고를 검토한 뒤 블로그 플랫폼의 `개인 프로젝트` 카테고리에 게시합니다. 하위 카테고리는 만들지 않고 RabbitMQ·Spring Boot·Retry·Jitter 등을 태그로 사용합니다.
