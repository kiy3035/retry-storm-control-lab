# 결정 기록

## 2026-08-31: 1단계 로컬 기반 구성

- Java 21, Spring Boot 3.5.16, Gradle 8.12.1을 사용한다. 현재 로컬 Java 21과 캐시된 Gradle 배포본으로 재현 가능한 조합을 선택했다.
- PostgreSQL 16.9와 RabbitMQ 4.1.4 이미지를 태그까지 고정한다.
- Flyway 계정과 애플리케이션 계정을 분리한다. 애플리케이션 계정은 `retry_lab` 스키마의 DML만 허용하고 DDL은 허용하지 않는다. 이후 단계의 실험 결과 및 DLQ 저장에는 쓰기가 필요하므로 Text2SQL 문서의 read-only 계정 규칙은 이 재시도 실험에는 적용하지 않는다.
- `.env.example`에는 값 없이 변수 이름만 둔다. 로컬 비밀번호는 실행할 때 생성하거나 사용자가 주입한다.
- 1단계에서는 연결과 마이그레이션만 검증한다. exchange/queue, 발행자, 소비자, 재시도, DLQ는 이후 단계의 비교 대상이므로 만들지 않는다.

## 명세 불일치

저장소 이름과 `PROGRESS.md`, 사용자 요청은 RabbitMQ 재시도 폭주 제어 실험을 정의하지만 `AGENTS.md`, `PROJECT_SPEC.md`, `CODEX_PROMPT.md` 본문은 Text2SQL 실험을 설명한다. 1단계에서는 사용자가 명시한 PostgreSQL·RabbitMQ 기반과 `PROGRESS.md` 단계표를 우선했다. 2단계 시작 전에 세 명세 문서의 정합성을 별도로 확정해야 한다.

## 2026-09-01: 코드 주석과 단계별 검토 방식

- 코드에 주석이 필요하면 반드시 한글로 작성한다.
- 각 단계가 끝나면 작업 내용과 변경 전후 비교를 중심으로 PR 설명을 준비한다.
- 최초 구현 시점에는 현재 디렉터리가 Git 저장소가 아니어서 PR 설명 문서만 먼저 작성했다.
- 이후 연결된 `kiy3035/retry-storm-control-lab` 원격을 확인하고 루트 작업 폴더를 `main`에 연결했다. 단계별 작업은 별도 브랜치와 PR로 검토한다.
