## 해석과 한계

Jitter는 이번 지수 대조군보다 짧은 구간의 재시도 집중도를 낮췄지만 Fixed보다 완료시간이 짧지는 않았습니다. 총 대기 시간이 달라 Jitter 단독 효과나 운영 성능 보장으로 해석하지 않았습니다.

25% 실패율과 100% 재처리는 합성 입력의 결과입니다. CPU·queue는 1초 표본, DB는 runtime SQL calls/s입니다. 기존 exactly-once·PROCESSING 자동 복구 한계도 유지됩니다.

무료 로컬 도구와 합성 데이터만 사용했고 비밀번호·payload·실행 로그는 커밋하지 않았습니다. 6단계가 마지막 계획 단계이며 자동 merge나 추가 운영화는 하지 않습니다.
